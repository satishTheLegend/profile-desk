# iOS design verification

Audit date: 18 October 2026, Asia/Kolkata. Baseline source: `44df481`; fixes below are subsequent working-tree changes. This review reads the actual production Swift, app plist/configuration, prompt requirements, acceptance ledger and retained evidence. It does not infer service or physical-device success from source inspection.

## Defects found and repaired

| Finding | Requirement / acceptance | Result and evidence |
| --- | --- | --- |
| A delayed callback from picker A could cancel picker B or deliver A's files under B's current owner. Both delegate methods used current mutable ownership without checking the originating controller. | REQ-08-005/008/021; REQ-12-009/010; AT-M03 | `NativeTransfers.swift` now checks exact picker identity before either callback changes state. The simulator fixture executes these actual delegate methods with two real `UIDocumentPickerViewController` objects. The retained baseline fails both cases; repaired runs also verify exactly-once completion, original file bytes and profile-specific destination. |
| The process-global plugin survived Flutter engine destruction and rejected every subsequent registration. It was not published, so Flutter could not deliver its detach callback. | REQ-05-015; REQ-08-005/024; AT-I10, AT-D09 | The plugin publishes itself, accepts detach only from its own registrar, covers/disposes its view, cancels authentication/transfers, disconnects channels/observers/network monitoring, and allows a replacement registration. Transfer cancellation and pending durable cleanup settle before the replacement initializes. Old events and view ownership become invalid. Cross-review added attachment checks after async preparation/authentication, detached guards on every host entry and queued lifecycle callback, and exact-controller revalidation before cancellation can dismiss UI. Already-started cleanup retains its durable database operation and completes before replacement startup. The fixture calls the actual Flutter protocol entry point, including wrong-registrar and late old detach cases. |

The baseline failure is preserved in `evidence/ios/engine-picker-detach-baseline-failure.json`. The intermediate 21-assertion callback/registration run passes in `engine-picker-detach-21-pass.json`. An expanded real-registry/open/reopen test failed in the standalone fixture's initialization; that result is retained in `engine-harness-initialization-failure.json`, rather than being relabeled a passing test. A final run against frozen production source passes **24 assertions** in `evidence/ios/engine-picker-detach-final-24-pass.json` and its adjacent `.log`. `engine-picker-detach-final-source-snapshot.json` records the exact source hashes checked before and after compilation, and rechecked after completion. The extra assertions reject captured old transfer/help/capability calls after detach. The simulator was deleted and no simulator remained booted.

The fixture compiles the production plugin, Pigeon transport, WebKit binding and transfer implementation against the pinned Flutter framework, targeting iOS 17 API availability. Registrar/messenger and presentation are test doubles. Native picker objects, callback methods and file I/O in this passing fixture are real. It compiles the registry and WebKit source but does not claim their initialization/open paths ran in this fixture. It is neither a real Flutter engine destruction test nor a real service upload test. No account pairing or message delivery is performed.

## Requirement checklist

`[x]` means the stated source/local evidence check is complete. An unchecked item remains required or conditional as described; it is not a failed architectural assumption unless explicitly identified as such.

- [x] REQ-09-001–005: public named persistent stores, UUID identity before WebView construction, iOS 17 deployment baseline, main-actor UIKit/WebKit work and explicit view disposal are present. Code: `SessionEnginePlugin.swift`, `BoundWebSession.swift`; existing 29 native tests and hosted isolation fixture support the stated synthetic scope.
- [x] REQ-06 allocation/registry: SQLite transactions reserve ten slots including incomplete and pending cleanup rows; alias normalization, stable identifiers, schema history, startup reconciliation, missing/quarantined states and minimal removed tombstones are implemented. Code: `ProfileRegistry.swift`; native registry tests execute these helpers.
- [x] REQ-07/08 ownership: profile/view/operation/generation handles, selection revalidation after inventory await, explicit cover checks, cleanup ownership independent of active selection and no production JavaScript/page-export interface are present. The new picker regression closes a native callback hole that Dart-only tests had not detected.
- [x] REQ-09-008/009: deletion releases clients, enumerates before public removal, persists actual failure as pending and never reconstructs a tombstoned store to inspect it. Existing hosted runs demonstrate real public "in use" failure/retry and nine unaffected neighbors; earlier failed runs remain evidence.
- [x] REQ-09-010 source portion: renderer termination covers/disposes the affected view and emits bounded recovery; inspection is disabled; iOS 18.4 open-panel API is availability-gated.
- [ ] REQ-09-010 runtime portion / AT-D09: actual iOS WebContent termination and memory-pressure recovery have not been induced. Existing Android termination evidence does not satisfy iOS.
- [x] REQ-12 navigation source/unit portion: exact HTTPS `web.whatsapp.com` host with default/443 port and no credentials; main-frame redirects blocked outside policy; user-activated ordinary external schemes routed to OS; TLS uses default trust; popups cannot allocate a second/default store. Code: `WorkspaceURLPolicy.swift`, `BoundWebSession.swift`.
- [ ] REQ-09-006/007, REQ-12 real-service portion: ordinary versus desktop rendering, all legitimate service navigation/App-Bound Domains behavior, conditional phone-number linking and real embedded service compatibility require authorized accounts and device evidence. The public desktop preference is a chosen implementation, not an executed A/B comparison.
- [x] REQ-12 upload local portion: private profile/transfer staging, bounded chunk copies, original view/operation and picker identity, multiple-selection forwarding, progress, cancellation and failed-copy cleanup are implemented; helper tests and native callback regression cover synthetic files.
- [ ] REQ-12-014 exact cleanup-on-success clause: successful import files remain until view disposal/profile removal/startup, because returning their URLs is not proof that WebKit has consumed or uploaded them. Immediate deletion would break deferred browser reads. Retention is tied to the view lifetime, not confirmed website delivery; no public browser upload-completion callback has been established. Classify this clause PARTIAL and document that limitation rather than claiming success cleanup.
- [ ] AT-M01–M04: actual Photos/document/cloud-provider pickers, zero-byte/large/low-space/revoked access cases and service delivery remain incomplete. iOS 17–18.3 uses WebKit's own picker; source guards on presented controllers are not proof of callback ownership in that OS path.
- [x] REQ-12 download source portion: actual WKDownload browser context, profile/transfer destinations, progress, cancellation, filename sanitization, explicit anchored system share and export cleanup exist. Download records include original handle/token; no cookie or credential export is used.
- [ ] AT-M08–M10: actual WKDownload HTTP and blob/decrypted media, share-sheet completion, iPad resizing/focus, low space and large transfer handling remain unexecuted. The transport harness uses fetch byte/hash checks and must not be cited as native download/share proof.
- [x] Conditional capture: camera/microphone/motion requests denied and camera/microphone purpose declarations absent. No calls, voice notes or background messaging promise is enabled. AT-M06/07 stay conditional-disabled.
- [x] REQ-13 lock source/unit portion: device-owner authentication fallback, setup checks, generation/foreground guards, opaque web and full-window covers, background media/transfer cancellation and no silent lock disable are implemented. `NativeLockState` tests verify late-auth races.
- [ ] AT-S01–S03 hardware portion: physical snapshot timing, cancel/lockout/enrollment changes, device passcode behavior and lock/picker interruptions remain unverified. Simulator state tests do not establish biometric or preview behavior.
- [x] REQ-13 restore source/unit portion: device-only Keychain secret plus excluded installation anchor/HMAC, backup exclusion for app-owned registry/staging, file protection and quarantine of untrusted restore are implemented. Code: `InstallationBinding.swift`, `ProfileRegistry.swift`.
- [ ] AT-D12 / AT-I12 / AT-S12: physical reinstall, restore/device transfer, browser-owned storage backup behavior and same-signature app upgrade remain incomplete. SQLite version-one reopen and synthetic provenance mismatch are narrow tests.
- [x] REQ-13 diagnostics local portion: production allowlisted renderer omits profile UUIDs, aliases, filenames/paths, cookies and session data under seeded marker tests. Production privacy manifest, original app branding and release configuration are present.
- [ ] AT-S05/06/08/11/12 release portion: full signed process-log/share-flow audit, real device inspectability, current store/service distribution evidence, signed archive and submission remain separate requirements. A native privacy manifest is not proof that the embedded website collects no data.
- [x] Synthetic storage scope: ten same-origin named stores; cookies/HttpOnly, localStorage, IndexedDB, CacheStorage/service-worker values; disposal/reopen; middle removal/replacement; channel isolation; HTTP-cache/WebSocket identity; 200 seeded switches. Existing final hosted 81-assertion and stress 631-assertion runs support only their recorded simulator scenarios.
- [ ] AT-I03: complete service-worker update/upgrade matrix remains partial even though registration/storage/reopen/cleanup pass.
- [ ] AT-I06: ten actual authorized accounts have not been paired.
- [ ] AT-I10/11: normal UIKit background→process relaunch and simulator reboot pass for two synthetic profiles. A preserved abrupt-termination mismatch followed by a passing replay leaves abrupt persistence unproven, and is not equivalent to ten real accounts.
- [ ] AT-I12/I14, AT-D05/06/11/12: signed upgrade, storage pressure/eviction, fault injection at every journal stage, physical restore and full pending-cleanup UI/runtime matrix remain partial.
- [ ] AT-I15: seven-day feasibility and fourteen-day beta retention have not elapsed or begun as authorized real-account runs.
- [ ] AT-M11/13/14 and performance targets: minimum iOS 17 hardware, current iPhone/iPad, VoiceOver, keyboard, large text, focus/orientation/resizing, thermal/battery and combined host+WebKit memory baseline remain unverified. Fixture app-process RSS excludes WebKit subprocesses; fixture navigation timing is not selector latency or real website usability.

## Commands and evidence boundary

Run the focused production-plugin regression with:

```sh
FLUTTER_ROOT=/opt/homebrew/share/flutter packages/session_engine/ios/NativeTests/run-engine-tests.sh
```

The runner creates and deletes its own simulator and uses a separate test-only bundle identity. Its ad-hoc signing is solely for local simulator execution. It does not modify production signing settings or access real accounts. The expanded fixture initialization error was not diagnosed conclusively; attempted test-host entitlements then failed at simulator launch. Those attempts are retained in `engine-expanded-fixture-launch-failure.log` and `engine-expanded-initialization-fixture.swift.txt`. They are fixture limitations, not a production entitlement workaround or an initialized-engine pass. A runner edit during an earlier active invocation caused a parse failure, retained in `engine-runner-input-mutation-failure.log`; the frozen final runner passes syntax checking and execution. Existing broader checks remain `NativeTests/run-native-tests.sh`, `run-storage-harness.sh` and the isolated Flutter shell runner.

The requirement ledger's `PASS` values must retain their narrow validation scopes. In particular, generic `native compilation, helper tests and hosted WebKit fixture` text does not establish every part of a compound media, retain-cycle, renderer or physical-device requirement. Final release completion remains open until the unchecked requirements obtain their named evidence.
