# iOS implementation and evidence

Access/evidence date: 18 October 2026 (Asia/Kolkata). This record distinguishes source, simulator execution, physical devices and real service access.

## Implemented ownership

`packages/session_engine/ios/session_engine/Sources/session_engine/` contains the registered Flutter/Pigeon plugin. UIKit, WebKit and native lifecycle mutations run on the main actor. The registrar exposes exactly one persistent platform-view host, `profile_desk/session`; each open constructs a new WKWebView with its named WKWebsiteDataStore already bound. Disposal releases delegates, view, media and references while preserving the store. No default persistent account store, cookie swapping, user-agent impersonation, generic webpage bridge, arbitrary JavaScript API or production inspection is used.

Native SQLite is the sole durable registry. Row decoding validates canonical UUID identities and required numeric/lifecycle fields; every pending cleanup must also reference an existing profile in a removal lifecycle before any store API, so a corrupt journal cannot retarget an available profile; malformed rows fail closed with a storage error before any store can be opened or deleted, instead of force-unwrapping corrupt values. Transactions reserve one of ten slots before named-store allocation. Alias validation, stable random IDs, ordering, user observations, preferences and cleanup stages are native. Startup processes all tombstones before any named-store constructor, reconciles public inventory, quarantines orphan stores and flags missing stores. Unknown stores are never assigned to a new account. A reservation interrupted before a store appears becomes quarantined and remains removable. Both quarantined and pending-removal profiles reserve capacity until actual cleanup completes.

Before cleanup or inventory, installation provenance is verified with a per-app device-only Keychain secret, an excluded random installation anchor and an HMAC proof stored in the registry. This binds installation provenance; it is not a cryptographic signature of every registry row. Missing/mismatched provenance quarantines existing registry entries and suspends their old cleanup journals; matching UUIDs cannot silently make them available. A new explicit removal remains possible. Every open enumerates current public inventory and revalidates ownership, lifecycle, foreground state and lock after that await; a disappeared store becomes missing instead of being silently recreated.

The integrated app exposed a cold WebKit inventory crash on iOS 26.5 before any WebView existed. Startup now creates and releases a blank ephemeral WKWebView before enumeration. It never navigates, uses no default persistent store and loads no named profile. The account view is constructed later, after startup cleanup. The integrated QA app subsequently launched to its welcome screen on iOS 26.5; the root UI evidence ledger records that runtime smoke check. The isolated hosted test also exercised cold inventory after this bootstrap.

Named-store deletion uses `WKWebsiteDataStore.remove(forIdentifier:)` after owned views/transfers are released. Failure remains `websiteWipePending`; it never reports Android's post-wipe `containerDeletionPending` stage. The cleanup operation survives selection changes and process death, and successful deletion removes profile staging/permissions before releasing the slot. Repeating a completed removal is idempotent. Unknown orphan stores remain quarantined; deletion does not manipulate WebKit files or claim forensic erasure/remote unlink.

Completed removal redacts alias, normalized alias, color, ordering, timestamps and authentication observation. Only the minimal profile identity/lifecycle and idempotency journal remain to prevent resurrection and recognize repeated requests. This is logical application metadata deletion, not a claim of forensic erasure of SQLite pages.

View ownership includes profile, view instance, operation and generation. Navigation readiness is separate from authentication. Reload callbacks validate their navigation object. Exact-handle reveal additionally checks eligible registry state, readiness, app-active state and native lock. Native main-frame URL checks accept only HTTPS `web.whatsapp.com`, no credentials and default/443 port. User-activated supported external links open through the OS; redirects and unsupported schemes are blocked. No TLS challenge bypass is present.

## Privacy and media

A native opaque cover protects the WKWebView during switching and locking. A second full-window cover hides Flutter settings/account aliases as well as web content before background snapshots. Its Unlock control emits a typed request to the shared coordinator, preserving one authentication controller. `lockApp()` sets native locked state and invalidates pending authentication. LocalAuthentication uses `deviceOwnerAuthentication`, including supported device-credential fallback. Enabling or disabling the preference requires successful OS authentication. A native generation ticket rejects late success/failure after a newer manual/background lock and requires foreground completion. Cancellation never clears a newer lock. Background always cancels owned transfers and suspends playback; camera/microphone capture requests are denied until their separate evidence gate is cleared.

On iOS 18.4+, the public open-panel delegate routes files through UIDocumentPicker. Completion belongs to the original profile/view and is called once; cancellation, disposal and background cancel it. A detached worker copies in 64 KiB chunks, checks cancellation between chunks, and removes partial output before returning failure. The main actor revalidates immutable ownership before delivering files; deletion awaits worker completion. Sanitized names have a UTF-8 byte budget with room for random prefixes and ordinary extensions. Imported data stays in profile-specific private staging and is removed on disposal/removal/startup recovery. On iOS 17–18.3, WebKit owns its file picker; modal presentation guards block switching, but callback behavior and photo/document flows remain device-validation requirements.

WKDownload retains browser-native authentication context. Destinations sanitize names and use private per-profile/per-transfer directories. Redirects require HTTPS. Cancellation completion is awaited before deletion can finish. Completed downloads offer an anchored system share sheet; temporary exports are removed after completion, switch/removal or restart. WKDownload exposes public NSProgressReporting; its KVO observation reports aggregate byte progress only when every active download has a known total. Import copies preflight regular-file sizes, report bytes across files with updates throttled to roughly ten per second plus start/completion, and validate both the original view and transfer token before delivery. Unknown totals remain indeterminate. Actual HTTP, blob/decrypted-media, cloud-provider, low-space and large-file behavior still needs device/service evidence. Capture/voice/calls are intentionally disabled. Exported copies in other applications are outside local removal's scope.

NWPathMonitor reports unknown, offline or reachable network-path observations without contacting the service. Reachable means an OS network path exists; it does not assert internet access, website readiness or authentication. Network changes never select a profile or reveal a view.

The database and staging parent directory are excluded from backup with supported Foundation attributes. File protection is configured for app-owned storage. WebKit controls its own website storage; this does not assert universal backup/transfer behavior. Registry/store mismatch leads to quarantine/missing state; physical restore/transfer testing remains pending. Diagnostic export is explicit and allowlisted through the production `NativeDiagnostics` helper. Executed tests seed alias/cookie/token/pairing/path/URL markers and verify they and profile UUIDs are absent from the actual export payload. Numeric OS version text and aggregate counts are allowed. These are export-payload tests; they do not establish that all OS or third-party system logs are free of sensitive data.

## Repeatable native checks

```sh
swift test --package-path packages/session_engine/ios/NativeTests --skip NamedStoreTests
packages/session_engine/ios/NativeTests/run-native-tests.sh
```

The first command runs pure production helpers on macOS; it intentionally routes the two WebKit tests to the second command, which runs the complete suite on iOS. The native runner selects the newest available iOS 17+ runtime and a compatible iPhone, creates one disposable simulator, waits for boot before starting tests, disables parallel test workers, and deletes only its own simulator afterward. `IOS_TEST_RUNTIME` and `IOS_TEST_DEVICE_TYPE` can select another compatible installed target. Boot is bounded to two minutes, each test to at most two minutes, and the whole xcodebuild invocation to ten minutes. Logs, `.xcresult` and machine summary remain in its printed `build/ios-native-<UTC timestamp>/` directory.

The isolated HTTPS six-storage test app is **outside the production plugin**:

```sh
packages/session_engine/ios/NativeTests/run-storage-harness.sh full
# Independently run messaging, HTTP cache/WSS, or the seeded 200-switch scenario:
packages/session_engine/ios/NativeTests/run-storage-harness.sh messaging
packages/session_engine/ios/NativeTests/run-storage-harness.sh transport
packages/session_engine/ios/NativeTests/run-storage-harness.sh persistence
packages/session_engine/ios/NativeTests/run-storage-harness.sh persistence-lifecycle
packages/session_engine/ios/NativeTests/run-storage-harness.sh stress
```

The script creates its own disposable iOS 27.0 simulator, one-day test CA under a private temporary directory, HTTPS server on localhost:8445, and a synthetic app identity with localhost App-Bound Domains. It trusts the CA only inside that disposable simulator, never the host or production app. Cleanup shuts down/deletes only the created simulator, stops its server and removes its private key. Output is under `build/ios-storage-harness/`; the full-mode wait is bounded to six minutes after launch, messaging/transport and each persistence phase to three minutes, and the 200-switch stress mode to thirty minutes. Navigation has a thirty-second deadline and JavaScript operations have shorter bounded waits. Separate output directories preserve each mode. Transport mode uses one identical cache URL with no Cookie/nonce Vary header, verifies a same-profile cache hit, checks another profile starts with its own marker, and reopens both caches. WSS probes verify server-observed HttpOnly handshake identity. A tiny synthetic fetch upload/download roundtrip verifies bytes/hash only, not the native picker or WKDownload. Persistence mode seeds two named stores, writes their test UUIDs, then explicitly terminates/relaunches the app and shuts down/boots the same simulator before rechecking all six stores. Each phase has a separate result JSON. The `persistence` mode terminates directly; `persistence-lifecycle` keeps the final WebView attached, launches Settings and observes the actual UIKit background event before termination. This is synthetic immediate persistence, not actual account or seven-/fourteen-day evidence. Test results are saved before fixture teardown so cleanup cannot mask an assertion failure. Run these simulator jobs serially on memory-constrained hosts. Requires the listed simulator runtime/device type, Xcode, Python and OpenSSL. No real service account is used or contacted.
