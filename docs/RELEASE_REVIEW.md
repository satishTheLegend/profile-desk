## Native dependency reproducibility

Repository-owned Gradle module locking is now implemented for `:app` and `:session_engine`, replacing the earlier recommendation-only status. The production app and engine lockfiles contain 232 and 264 coordinate records respectively at this review. The isolated QA app has its own 248-record lock at `tests/device_flows/flutter/android-app.gradle.lockfile`, including the integration SDK's native dependencies. The module-lock hashes are preserved in the source-boundary review JSON. The final production incremental build completed in 16.4 seconds without `--write-locks` (`evidence/build/android-production-unsigned.txt`); the isolated ARM64 QA build also passed without rewriting its separate lock.

`io.flutter:*` coordinates are deliberately excluded from these module lockfiles because the pinned Flutter SDK selects its engine artifacts according to the requested ABI. This prevents an ARM64-only test from requiring unrelated ABI artifacts. This exclusion is explicit scope, not a claim that every native dependency is locked. Buildscript/plugin/Flutter composite dependency locking and cryptographic verification metadata are not established by these module locks. The official Gradle 9.3.1-all distribution checksum is pinned to `17f277867f6914d61b1aa02efab1ba7bb439ad652ca485cd8ca6842fccec6e43`. Dart locks are enforced by bootstrap; CI actions use fixed commit SHAs.

The QA native lock can be refreshed with `JAVA_HOME=/opt/homebrew/opt/openjdk@17 python3 tests/device_flows/run_shell_integration.py --prepare-only --refresh-native-lock`. This selects the isolated Gradle project with `-p`, requires matching wrapper properties, rejects failed dependency configurations even if Gradle's report task exits zero, and does not launch a device. A subsequent no-write build is required before accepting a changed lock.

Checksum metadata can be bootstrapped separately following Gradle's [dependency verification](https://docs.gradle.org/current/userguide/dependency_verification.html) guidance, but trusting the currently downloaded bytes is not an authenticity audit. Complete configuration coverage, independent artifact checks and dependency advisory review remain release work.

The first isolated iOS attempt stopped before installation because `simctl listapps` emitted OpenStep plist, which Python plistlib does not parse directly. The failure and owned-simulator cleanup are preserved in `evidence/build/ios-isolated-qa-inventory-failure.*`. The parser now uses bounded system plutil conversion for that format, retains direct XML/binary support, and rejects invalid shape/size/timeout. Eight additional regressions include actual OpenStep conversion.

## Remaining release boundaries

The independent design audit found and repaired the native lifetime defects described above. Required Android authenticated/blob download/save/share remains an essential release gap. REQ-12-014 is also partial: successful iOS upload staging persists until view disposal, profile removal or startup because URL delivery does not prove WebKit consumption/upload completion. Immediate deletion could break deferred reads. Current unsigned binaries pass artifact inspection and the new package manifest records exact output/source hashes. Post-package consistency verification passes in `evidence/design-audit/final-package-verification.json`; it does not attest compiler inputs or release readiness. Physical/provider coverage, real-account media, signed migration, elapsed retention and the full acceptance matrix remain governed by platform evidence and `acceptance.csv`.

No account pairing, live messages, service credential export, signing-account access, publication or store submission was performed by this review. Source declarations disabling inspection cannot prove runtime inspection remains disabled under every provider/OS defect or later signing/build change.
