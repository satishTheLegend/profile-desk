## Native WebKit probe

[ios-result.json](ios-result.json): 37 assertions pass on a disposable iOS 26.5 simulator, with `PASS_WITH_LIMITATIONS`. Public LocalStorage serialization restores into a fresh named store; separate cookie transfer survives closing and reopening that destination. Native requests for IndexedDB, cookies, workers, mixed types and all website data specifically reject as unsupported. Seeded plain IndexedDB data, caches and workers remain absent after LocalStorage restore and destination reopen.

The in-memory nonextractable key remains usable and rejects raw export. Persisting that key in IndexedDB throws `DataCloneError` in this ad hoc simulator app; this is recorded as unavailable, not a passed stored-key roundtrip or evidence about WhatsApp's actual keys. [Cleanup](ios-cleanup.json) confirms removal of the owned simulator, loopback server and temporary certificate; the app separately verified removal of its two owned stores. All [probe source hashes](ios-source-snapshot.json) match the final run, and [verification](ios-verification.json) confirms no owned simulator remains. Destination persistence here means view close/reopen, not process restart, reboot or cross-device transfer.

Four earlier failures are retained under `prior-ios-failures/`: initial navigation timeout, a seed failure later identified as the key-cloning `DataCloneError`, the instrumented key-cloning failure, and a simulator first-boot timeout before any storage assertion. The successful run used a bounded second boot wait on its owned simulator. These failures were not interpreted as unsupported archive APIs.
