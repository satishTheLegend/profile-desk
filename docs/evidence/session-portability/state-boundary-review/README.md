# Public storage and worker boundary review

19 October 2026. This is static analysis of bounded anonymous public source, with [asset hashes and provenance](source-provenance.json). No official client/worker code was executed; no account, profile, conversation, credential or real key was accessed. Public JavaScript stays in ignored local build storage. Per-request bootstrap tokens, root bodies and browser cookies were discarded; nonsecret public build revision metadata is retained. Disposable-browser cleanup passed.

The [Worm review](worm-ear-findings.json) maps the remaining known HKDF consumer to four encrypted pending-action queues. Records use versioned secretbox envelopes and master-dependent primary/index hashes. A fresh-master migration must also rebuild those hashes. Opening the ordinary queue initializer immediately starts resend, key-share and deletion drains; that initializer is unsuitable for a passive export. Replaying copied pending actions can repeat remote effects, while dropping them would silently reduce coverage. This requires an explicit consistency/replay policy and synthetic tests. It is not evidence that the queues contain the complete media archive.

The [version and service-worker review](version-service-worker-findings.json) establishes that `VERSION_STR` may be a generic `3.0.0.d`. A specific SW revision cannot authenticate unrelated earlier frontend assets. A production adapter still needs an exact compatible live runtime contract.

Conditional push/periodic paths can initialize and mutate stores without window clients. Their presence in source does not establish reachability in Profile Desk's WKWebView: push requires permission, subscription and treatment state; periodic sync excludes recognized Safari. The actual platform capability/lifetime boundary remains unverified. `STOP_COMMS` stops narrower communication work and supplies no all-store flush or irreversible writer fence.

Independent consistency review also found that Signal flushing covers selected tables, catches failures and does not stop new producers. Transaction-start counters, rendering callbacks and bounded queue waits cannot establish a whole-profile committed snapshot. Normal client startup initializes keys, preferences and workers before a late importer could run. The passing [empty-origin fixture](../origin-bootstrap/README.md) avoids that destination-startup problem for synthetic storage only.

Native-display source review supports a **candidate** restricted to the first official view in a genuine native process, with a process-owned irreversible admission latch, exact current authenticated socket state/stream, account binding, successful nonmutating lock reads and compatible runtime identity. `MAIN`/cached sync alone are insufficient. Missing lock duration can legitimately mean disabled; malformed/legacy/unknown state cannot be repaired to obtain eligibility. Service-worker notification/call callbacks count as official interaction. The candidate is not implemented or authorized for live activation by this review. Replacement navigation completion does not prove old-context destruction.

Open product gates remain complete state/schema coverage, all-writer capture, pending-action behavior, fresh key/salt bootstrap, an encrypted native archive and independent authenticated cold restore without relinking. No complete backup, live native port or deployment is claimed.
