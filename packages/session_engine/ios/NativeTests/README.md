# iOS native verification

`run-layout-resource-tests.sh` verifies the production Swift Package Manager resource declaration, executes the production `Bundle.module` loader in a small Foundation host, checks that the bundled file is regular and matches the canonical JavaScript SHA-256, and proves that a stale resource fails manifest evaluation even through Flutter-style package symlinks. After editing `packages/session_engine/layout/workspace_layout.js`, run `sync-layout-resource.sh` to refresh the generated SPM copy. `sync-layout-resource.sh --check` performs a read-only byte check for routine verification, even if SwiftPM reuses a cached manifest. The package manifest rejects missing, stale or symlink copies; CocoaPods continues bundling the canonical source directly.

`run-viewport-tests.sh` checks the actual production workspace/host against controlled hidden-overflow and responsive HTML. It covers desktop fit, host resizing, native coordinate conversion, privacy cover, disposal and the development-only browser identification policy. See `ViewportHarness/README.md` for the distinction between fixture geometry, native pinch configuration and actual physical pinch/keyboard behavior. Apple CI runs this suite sequentially with the other native suites; the remote workflow has not been executed locally.

The viewport fixture also bundles the production layout adapter in its isolated content world. It verifies readable phone-width panes, fallback while structural hooks are unavailable, late activation only for an eligible foreground view, Original → Chats recovery, portrait/landscape/split/tablet fit, keyboard-height resizing, cover interception and absence of the adapter API in page JavaScript. These checks use supplied HTML with a controlled base URL; they do not inspect a live signed-in service page.

From the repository root, `packages/session_engine/ios/NativeTests/run-native-tests.sh` runs the existing native helper and named-store XCTest suite on its own simulator. `run-storage-harness.sh` runs the independent synthetic HTTPS storage fixture; its accepted modes are listed in that script.

`packages/session_engine/ios/NativeTests/run-engine-tests.sh` compiles the actual production Swift plugin and Pigeon code against the installed Flutter SDK. Set `FLUTTER_ROOT` if the pinned SDK is not the `flutter` on PATH. It targets the iOS 17 API baseline and selects an available iOS 17+ simulator, or `IOS_TEST_RUNTIME` when supplied. It creates, runs and deletes only its own simulator.

The engine fixture checks stale UIKit picker result/cancellation isolation, exactly-once completion, file bytes and per-profile staging. It calls the actual Flutter registration/detachment entry points, including wrong and old registrar ownership, channel removal, re-registration and rejection of detached host calls. Registrar/messenger and UI presentation are doubles; picker objects, callback implementation and file copies are real. It does not execute a real Flutter engine teardown or live-service upload. Production source and fixture hashes are checked before/after compilation and retained with results under the printed `build/ios-engine-*` path.

Account setup coverage includes stale/locked document-picker callbacks, allowlisted metadata reads, export completion and cancellation, and removal of private staging. The Foundation XCTest suite validates archive byte/depth/type/key limits, duplicate property names (including escaped names), whole-batch transaction rollback, fresh store IDs, unknown authentication, opt-in appearance, destination security preservation and installation-bound allocation-journal recovery. Metadata import always requires relinking; no test claims signed-in session migration. Actual system document-provider presentation and authenticated service behavior remain device checks.

Do not edit fixture inputs or the running shell script during execution. Serialize simulator suites on the development host to avoid resource contention. All test bundle identities and fixtures are separate from production. No real account linking or message operation is performed. Broader initialized Flutter/native behavior belongs in `tests/device_flows/run_shell_integration.py`; hardware, authenticated service media and elapsed retention remain separate evidence.
